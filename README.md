# LX Music 收藏同步（lx-favorites-sync）

一个 Folia 模组：把 **LX Music 的「我喜欢」** 自动同步到 **Folia 的本地收藏（Liked Songs）**。

它**不下载、不搬运音乐文件**：LX 的「我喜欢」是数据源，模组负责把它与你**已有的本地音乐文件**精确匹配，匹配到的歌曲才会写进 Folia 收藏。

## 特性

- 不上传任何数据、不发起任何网络请求、不常驻后台、不设置开机自启。
- 只同步“本地确实存在”的歌曲：直接从 Folia 本地曲库匹配。
- 歌名、歌手、时长三字段精确匹配；同名不同版本（Live、伴奏、重制等）不会互相误配。
- 多份文件同时合格时，优先"文件名与歌名完全一致"的那份；最优文件已被更早的收藏占用时，自动顺延到下一份合格文件。
- 新歌入库依赖 Folia 自带的本地扫描：用 Folia 的「重新扫描」或开启「自动扫描本地文件夹」即可（模组不会代替 Folia 扫描目录）。
- 内置「本地缺失」面板：列出没有匹配到本地文件的收藏，并标注哪些是“已下载但还没被 Folia 收录”，对症给出提示。
- 「同步历史」：每次收藏变化都会记录（时间、新增 / 移除明细），可在模组设置里任选一条回退；回退前也会先记一份当前状态，回退本身同样可以再回退。
- 手动执行「完全同步」且会移除收藏时，需要再点一次同步确认（10 秒内有效），避免误删。
- 播放器进度条旁有「一键同步」按钮：点一下立即同步，悬停可看上次同步结果。
- 两种模式：`完全同步`（以 LX 为准）与 `只增加`（只追加不删除），在模组面板的「同步设置」里直接选择。

## 安装

### 从模组市场安装（推荐）

在 [Folium 模组市场](https://folium-compound.cielaniska.top/) 搜索 `lx-favorites-sync`，把下载的 zip 拖进 Folia 的模组面板即可。

### 手动安装

1. 打开 Folia →「设置 → 实验室」，开启模组系统。
2. 把 `lx-favorites-sync` 文件夹压缩成 zip（zip 顶层就是这个文件夹），拖进 Folia 的「模组管理」面板；也可以直接把该文件夹复制进 `%APPDATA%\Folia\mods\`。
3. 启用「LX Music 收藏同步」，并在确认弹窗中确认一次。

如果 LX 的下载目录还没有导入 Folia：在 Folia 的「本地音乐」页面把它导入一次。建议再开启设置里的「自动扫描本地文件夹」，这样以后 LX 下载的新歌会被 Folia 自动收录。

## 使用

Folia 命令面板（`Ctrl+K`）中的命令：

| 命令 | 作用 |
| --- | --- |
| `同步 LX Music 收藏` | 立即手动同步一次 |
| `恢复最近一次变化前的收藏` | 回退到最近一次收藏变化之前（只动收藏歌单；回退前的状态会先记入历史，可再回退） |
| `查看本地缺失歌曲` | 打开「本地缺失」面板 |

同步模式、上次同步结果与「同步历史」都在 Folia 模组面板的「同步设置」里：展开「LX Music 收藏同步」，可直接切换同步模式；展开「同步历史」可以看到每次收藏变化的记录（时间、触发方式、`+N / -M`，点开带歌曲明细），每条都能单独回退。回退需要点击两次确认，不会误触。

播放器面板中还有「本地缺失」标签页，支持按歌名 / 歌手 / LX 原顺序排序，并可一键重新同步。
播放器进度条右侧还有一个「同步」图标按钮：单击立即同步（悬停显示上次同步结果）。

## 缺失提示说明

「本地缺失」面板会给出两类标记：

- **已下载未收录**：LX 下载记录里这首歌的文件确实存在，但 Folia 曲库里还没有 → 多半是下载目录还没被 Folia 扫描，去「本地音乐」重新扫描对应目录即可。
- **疑似在下载目录**：LX 下载目录里存在文件名同时包含歌名与歌手的文件 → 可能只是还没入库，也可能是另一个版本。
- **共用本地文件**：极少数情况下（多首收藏只对应同一个本地文件、且没有其它合格文件可用），会有一首没能单独占位；面板会显示“另有 N 首与其它收藏共用同一个本地文件”，不需要手动处理。

缺失快照最多保存 500 条（Folia storage 整个文件上限 1 MB）；缺失更多时会显示总数、并只列出前 500 条。

## 匹配规则

- **歌名、歌手**：NFKC 规范化（全半角统一）、忽略大小写与标点空格、去掉 `feat.` 附注后，必须完全相等。
  版本字样（如 `(Live)`、`-insturmental`）保留在歌名里参与比较，因此不会与普通版本互配，也不需要维护“后缀词表”。
- **时长**：LX 记录为 `mm:ss` 整秒，必须等于本地文件时长的**截断值**或**四舍五入值**（两者必居其一，无容差区间）。
  例如 LX 04:06（246 秒）与 246.7 秒的文件一致；与 250 秒的文件不一致，会显示为缺失而不是乱配。
- 匹配优先取文件元数据；多份文件同样合格时，优先文件名本身就能解析出与 LX 完全一致的 `歌名 - 歌手` 的那份（例如标签同为「夏恋」时，优先 `夏恋 - Otokaze.flac`，而不是 `夏恋-insturmental - Otokaze.mp3`）。
- 最优的那份文件已被更早的收藏占用时，会自动顺延到下一个同样合格的文件（例如同名文件的另一份拷贝）；只有当所有合格文件都被占用时，才会出现“与其它收藏共用同一个本地文件”的情况，面板会单独说明。

## 原理与数据

**读取**

- LX Music 数据库 `lx.data.db`：`my_list_music_info`（`listId = 'love'`）、`download_list`、`config_v2.json` 中的下载目录设置。全程只读，不写入 LX 的任何文件；直读失败时会把 `lx.data.db`（连同 `-wal` / `-shm`）复制到系统临时目录再读，读完立即删除。
- Folia 的 IndexedDB（`KineticPlayerDB`）：本地曲库 `local_music`（只读）、收藏歌单 `local_playlists`（读取 + 写入，见下）。
- LX 下载目录：仅列出音频文件名（用于缺失提示），不读取文件内容；扫描限制最多 12 个根目录、250 个目录、深度 6、5000 个文件，避免卡顿。

**写入**

- Folia 的收藏歌单（`local_playlists` 里 `isFavorite` 的那一条）：更新 `songIds`、`updatedAt`、`isFavorite`（必要时补上 `name`）——这是模组的核心功能。「读—改—写」在同一个 IndexedDB 事务内完成，`只增加` 模式会与事务里的最新 `songIds` 取并集，尽量不覆盖你同时进行的收藏改动；写入后触发宿主的 `folia-local-music-updated` 事件让界面刷新。
- 其他歌单、`local_dir_handles`、本地音频文件一律不动。模组不调用 Folia 的任何内部函数，但确实直接读写 Folia 私有的 IndexedDB 结构，因此把 `folia` 版本范围钉在 `>=0.7.17 <0.8.0`。
- Folia 官方 `storage`（`folium.storage` / `api.storage.data`，即 `mod-data.json`，上限 1 MB）：设置、上次同步结果、缺失快照。缺失快照最多 500 条，状态的下载目录最多 12 条；写不进去时会记录日志并提示，而不会悄悄改存到别处。
- 模组专属数据目录 `%APPDATA%\Folia\mods-data\lx-favorites-sync\`：
  - 日志 `lx-favorites-sync.log`（超过 1 MB 轮换一份 `.old`，旧档超过 7 天自动清理）；
  - 同步备份 `backups/`（最多 30 份，只在收藏真的发生变化时写入；写入收藏之前先写备份，备份失败就不改收藏；回退前也会先记当前状态，所以回退本身可以再回退）。

模组**不写** Folia 的 `local_dir_handles`，不改动 Folia 的目录管理；本地音频文件不会被移动、删除或重命名。

**旧版数据迁移（一次性）**

- 旧版（≤1.6.3）散在 Folia userData 根目录的文件会在启用模组时处理：删除旧的 `lx-favorites-sync.log` / `.log.old`；把 `lx-favorites-sync-backups` 整个搬进模组目录；发现 `lx-favorites-sync-settings.json`、`lx-favorites-sync-status.json` / `.txt` 时先迁移到官方 storage 再删除。以上都是固定文件名，不会动到你自己的文件。
- 旧版曾把同步状态、缺失快照写进 Folia IndexedDB 的 `api_cache`（键 `lx-favorites-sync-state` / `lx-favorites-sync-missing`）；新版本首次读取时会迁移到官方 storage 并删除这两个旧键，之后不再往 `api_cache` 写任何东西。

## 隐私

模组不发起任何网络请求，不收集、不上传任何数据，只在你的电脑上读取上面列出的数据库与文件。

## 兼容性

- Folia：`>=0.7.17 <0.8.0`（需要开启实验性模组系统）。
- 平台：Windows 已测试；macOS / Linux 按 LX Music 的默认数据目录做了理论支持（未实测）。
- LX Music 数据目录非默认位置时，可设置环境变量 `LX_MUSIC_DATA_DIR` 指向包含 `lx.data.db` 的目录。

## 目录结构

```
lx-favorites-sync/       # 模组本体（投稿时指向这个目录）
├─ mod.json
├─ main.cjs              # Node 端：读取 LX 数据库、存取设置/状态、写日志与备份
├─ client.js             # 渲染端：匹配、写入 Folia 收藏、命令、面板与同步历史
└─ preview.jpg           # 模组市场介绍图
```
